# 0.3.11 设备检查

版本0.3.11/build16；本环境没有真机或UIKit模拟器。

| 项目 | 操作和预期 |
| --- | --- |
| 半屏轻点 | 上/下半屏后轻点底部短线、轻微手指抖动，窗口位置、比例和半屏状态不变 |
| 等比拖动 | 明确拖动超过14pt后才切换比例；窗口从原位置附近转换，标题不会移到系统下拉区域 |
| 标题触达 | 普通窗口移到最上方后，从标题空白处下拉可拖动，不必从状态栏/通知区域起手 |
| 挂起还原 | 普通自由、等比、上下半屏、全屏分别挂起到右上角；点击缩略窗恢复先前位置/尺寸/模式 |
| 挂起设置 | 设置 → 挂起小窗，调整18%–50%大小和6种比例；已挂起窗口更新外形，恢复后原窗口不受影响 |
| 多窗与旋转 | 同时挂起2–4个窗口，横竖屏切换后缩略窗不出安全区、不重叠；恢复后窗口按当前屏幕容纳 |
| 输入归属 | 挂起A后输入焦点不能继续属于A；点击缩略图只还原，不点击到被缩小的App按钮 |
| 收纳/关闭 | 挂起窗可从面板最小化/关闭；已关闭的缩略窗不得被延迟回调重新创建 |
| 加载后挂起 | B加载期间把A切到原应用，待B在收纳状态完成加载，再从面板挂起B；必须出现右上角缩略窗且可还原 |
| 兼容模式 | 面板对应App的… → 兼容显示并重新打开；固定系统画布启动，外窗大小/全屏/半屏/挂起状态保留 |
| 兼容取消 | 重开期间锁屏、切后台或关闭浮动模式；不出现晚到的新窗口 |
| 870/Telegram | 分别普通与兼容打开，等待至少12秒，再导出日志；说明是整窗空白，还是文字/按钮可见而图片不加载 |

显示诊断无需先点20秒采集：每次guest启动自动有guest.application_profile及guest.render_probe。图层数量0与unavailable含义不同；有图层也不等于像素正确或媒体加载成功。不要公开原始诊断中的其他App信息。

挂起是缩略显示并保留会话，不是暂停目标进程；不保证后台游戏/网络任务无限执行。兼容重开可能使表单或页面状态重置，必须由明确菜单动作触发。
