# 0.3.8 反馈处理

0.3.7用户确认独立底栏改善了等比缩放触发；批评上下控件占用大、复制输入板不能解决实际输入、打开原应用有白屏。本轮没有新诊断JSON，不能把白屏或直接键盘问题声明为真机已修复。

窗口chrome从48+44=92pt改为28+18=46pt。整条底部保留为宿主区域，避免将缩放命中扩大到guest内；底部仅保留淡底、中央短横线和右下弧。右上自由角标跟随标题栏顶部额外inset，保持在guest以外。纯几何回归先在旧92pt实现失败，再验证减少的占用、底条与guest不相交、半屏/全屏和等比计算。

原应用切换存在明确源代码问题：旧版只detach/minimize view，目标FBScene仍存在。本版从窗口注册表移除目标，保存几何，释放其显示内容；MWSceneSession调用运行时ABI检查的deactivate:，有回调后再清理输入登记、invalidate presenter、destroy owned scene，并通过sceneWithIdentifier:确认本地场景不存在。只有这些步骤成功才发送普通启动请求。等待2秒超时或API缺失/清理失败则关闭目标并提示，绝不并行创建另一目标小窗，也不终止App进程。

MWNativeHandoff纯C状态机覆盖未停用前不能打开、未释放前不能打开、超时、重复回调、清理失败和旧代际取消。Workspace以目标对象身份和generation保护回调；锁屏、后台、切换宿主工作区、全部关闭会取消，恢复可见不会重新打开目标。其他窗口仍可收纳/恢复，加载中的托管画面移出层级并保持不可见。

独立复核指出等待期间边缘面板可能再次打开并把遮罩留在原应用上方；已禁止交接期间展开面板，并在打开原应用前再次清除面板。失败小窗若此前已正确关闭，也可直接继续普通启动；清理失败标记累积保存，后续空清理不能覆盖失败状态。

接口声明核对固定MTACS/iOS-17-Runtime-Headers提交d1d960dfaa4107765dd7fcf891e4967c0930d5fd中的FBScene/FBSceneManager。直接guest键盘仍缺少设备证据；本轮复查已有可见性环境、仲裁与输入活动观察路径，没有继续叠加未验证的私有焦点改动。复制输入板仅保留面板可选入口，移除底栏两个按钮及输入板的原应用捷径。Github发布说明分别列出修复、调整、新增、移除和仍未解决的直接输入限制。

离线测试、原生构建、静态分析、独立复核、归档重建和发布检查结果记录于release验证附件。设备检查见device-validation-0.3.8.md。
