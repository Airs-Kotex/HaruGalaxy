# HaruGalaxy 0.3.3 真机验收

这是供真机验证的修复候选版，版本 0.3.3 / build 8。已确认 0.3.2 入口的三个 Objective-C 方法名没有覆盖 UIKit 回调；修正接口和主机验证不能代替设备触摸投递。已有设备为 iPhone 14 Pro Max / iOS 16.2（20C65）。

使用 TrollStore 覆盖安装 `HaruGalaxy-0.3.3.tipa`，保留详细日志。按下表逐项测试；0.3.1 原始包继续作为回退入口。

| 项目 | 操作与通过条件 |
| --- | --- |
| 应用内入口 | 打开一个 App 后点击入口，能打开/关闭面板；先记录普通窗口结果 |
| 浮动入口 | 开启浮动工作区后，在桌面及其他 App 界面点击入口，各重复 10 次，每次切换一次面板 |
| 收起后点击 | 左右两侧收起后，各点凸起及略偏内侧位置 10 次；出现按下展开反馈并打开面板 |
| 动画中点击 | 自动收起期间按下，或快速开、关、再开；不丢失点击和重复激活 |
| 短拉与长按 | 向内短拉约 20–30 点后松手打开，拉回原位置松手取消；原地长按后松手打开 |
| 移动与取消 | 长按振动后拖动才移位；振动前的小偏移不导致拖动；跨边缘、锁屏中断和旋转后仍可再次操作 |
| 保持展开 | 设置 → 浮动工作区 → 入口保持展开，退出重开保持设置；关闭后恢复收起 |
| 面板与真实内容 | 开应用、恢复、最小化、全屏、关闭和设置均可用；App 内容可点按/滚动；面板外一次点击仅关闭面板 |
| 多窗口与流畅度 | 保留 2–4 个窗口，开关面板 20 轮；状态及时刷新，最后一个关闭后空态正确；对比入口反馈、面板准备和内容重排是否卡顿 |
| 前后台与输入 | 锁屏解锁、前后台切换和横竖屏后重复入口点击；搜索键盘及主应用输入兼容路径仍可用 |
| 缩放和半屏 | 右上自由、右下原始系统比例和上下半屏继续工作 |

入口固定触摸区域是 56×76 点，可见收起凸起 12×60 点。触摸区用于入口操作，如挡住常用 App 按钮，可拖到另一侧或不同高度。

出现问题后先在设置标记问题并导出日志，说明当时在普通/浮动模式、左/右侧，以及点击、拉动还是长按。可以使用 `python3 scripts/inspect_diagnostics.py <日志路径>` 查看 `input_pipeline`。

新增证据的边界：

- `overlay.interaction_ready`：记录浮窗启用时的 hidden、interactive、key 状态，仅代表该时点。
- `overlay.hit_test`：根窗口命中查询，前三次后最多每秒记录一次，含原生与 overlay 命中类名；**查询不是实际触摸投递**。
- `input.edge_delivery`：窗口 `sendEvent:` 观察到目标为本应用入口的按下、松手或取消；不会记录 App 内容、键盘或连续坐标。
- `edge.touch_begin/rejected/end/cancelled`：UIControl 回调和判定的执行证据；若有 delivery 却没有 begin，可进一步查系统取消、可交互状态与回调绑定。
- `edge.activate`：入口请求面板；`panel.blocked` 表示当前呈现的控制器阻止打开，`panel.open` 表示打开流程完成。
- `panel.open.preparationMs`：同步准备/布局时间，不含输入送达、GPU 或屏幕呈现；`rowsCreated` 是累计创建条目数，不变窗口反复打开应不增长。

日志缺失可能来自关闭详细记录、抽样、滚动覆盖或不同 session，不能仅凭某条事件不存在认定根因。此候选版没有测得 FPS、触摸成功率或百分比提速。
