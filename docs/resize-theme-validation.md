# 0.3.17（23）：缩放模式切换与相邻功能验收

本版修正自由与等比反复切换后仍保留旧画布比例的问题。四角拖动继续保持现有画布作为预览，成功松手后普通自由模式采用最终内容区域，普通等比模式恢复系统画布。取消、失败或不足14点的拖动保持原状态，原始画布始终使用设备尺寸。

本版基于0.3.16（22），成功松手时允许应用按所选模式重排，取代0.3.16的“松手后仍保持旧画布”行为。主题与方向回退沿用0.3.16。这份清单记录仍需设备验收的项目，离线检查与代码审查通过不代表以下设备项目已通过。

## 行为和证据范围

四个缩放入口在拖动期间保留正在显示的App逻辑画布，外窗变化由呈现容器等比适配，必要时留边。自由入口独立改变外框宽高；等比入口使用设备当前方向的系统比例作为外框内容区比例。成功松手后，先完成最终内容区域布局，再按自由视口或系统画布更新应用尺寸并统一提交；自由视口仍遵守应用自身的方向约束。普通模式的半屏、最大化允许布局变化；最大化还原恢复保存的窗口画布。原始画布从启动起就使用设备画布。

浮窗与应用窗口的主题偏好统一同步。自动主题通过可用的UIKit系统样式通知及普通场景trait回调更新浮窗，不把浮窗自身的旧样式当作系统来源。私有getter不可用时，新连接/进入前台/样式发生变化的普通场景可更新降级缓存，未变化的后台场景不作为新来源；较旧的排队通知不能覆盖已接受的新快照。私有通知、键或getter不可用时不能保证所有系统版本的后台投递。

可见工作台接收新的UIDevice方向通知，即使主应用已进入后台；启动时的后台缓存值仍被拒绝，近期CoreMotion输入仍优先。此项修复的是代码中可复现的通知过滤条件，当前iPad诊断不能证明手机故障原因。

## 设备检查

1. iPad横屏普通模式与原始画布模式各打开一个App。记录首屏顶端、底端和左右可见内容，两组对角入口分别反复执行“等比→自由→等比”和“自由→等比→自由”，每组至少五轮。拖动预览应完整等比、无拉伸；普通模式每次成功松手后，自由入口采用最终内容区域、等比入口恢复当前方向的系统画布，允许一次应用重排，不应永久沿用上次模式的比例。原始画布始终设备尺寸，比例不同时允许留边。iPhone分别重复。
2. 轻点或移动不足14点应保持原状。缩放中取消、转动设备、锁屏、切回应用工作台应正确终止手势。旋转后检查触摸位置、底部内容和安全区，不能只看日志尺寸。
3. 普通模式半屏后拖离再缩放；最大化后还原；挂起/最小化后还原。最大化和半屏允许App重排；四角拖动中不连续改变内部宽高，成功松手采用本次模式。还原后检查画布与方向成对恢复。原始画布在半屏/最大化仍保持设备画布。
4. 工作台在浮窗时直接切系统浅色→深色→浅色；再测试App偏好“浅色”“深色”“跟随系统”，覆盖面板、设置页、边缘入口、窗框。切回自动后不能被先前手动样式锁住；不应需要重建浮窗。
5. 浮窗隐藏/锁屏期间切主题，恢复后检查；应用窗口/浮窗来回迁移、普通场景断开/重连后再切主题。检查导出中的appearance来源和实际窗口样式，但以可见UI为准。
6. iPhone单独采集新日志：从竖屏转左右横屏，再平放，覆盖应用内/浮窗、系统旋转锁开启/关闭、锁屏恢复。记录主应用状态、方向来源和目标App；仅竖屏App继续遵守自己的方向声明。
7. 在横屏工作台首次打开仅竖屏App，以及竖屏工作台打开仅横屏App，分别使用宽、窄普通窗口；应用方向首次确定时不应把已经正确的画布宽高再交换。检查失败重试、恢复为最大化后再还原，以及会话建立后的正常旋转：启动布局正确，后续真正切轴只交换一次。

本轮离线C回归增加双向反复切换、终态画布选择、受限方向与原始画布，并保留内容角点、初始画布、半屏/最大化和恢复等既有回归。独立审查另验证9216个四角阈值/终态组合及768组五轮双向切换，属于Core与UI顺序等价模型。主题和方向沿用的回归覆盖后台新通知/旧缓存/过期代次、getter不可用时的降级、手动转自动和通知/快照交错。原生构建与审查不能替代以上触摸、渲染、系统事件投递验收。
