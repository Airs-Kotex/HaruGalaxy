# 0.3.2 触摸回归与撤回记录

2026-11-09，用户反馈升级后悬浮窗点击无响应，在不同界面都无法通过点击操作，并要求撤销 0.3.2 发布。此前设备记录为 iPhone 14 Pro Max / iOS 16.2（20C65）；本次反馈没有附带新的诊断 JSON，不能据此认定是整个系统触摸失效、主线程阻塞或某个具体接口造成。

撤回时检查到 0.3.2 Release 已不存在，残留 tag 仍指向 `e28b4204d14d52de4a90ced452fed62c2323b39b`。已移除该 tag，并通过提交 `398c901693a76af4efc694a0fe3d58e0129f78e3` 完整撤销该版本变更。应用代码、资源和测试恢复到发布前 `f7811cd25fa8ffe3f7b25d63d3706d02f80f320e` 的状态，版本为 0.3.1 / build 6；原始变更留在 Git 历史中。README 与 CHANGELOG 另行补充撤回说明。现有 v0.3.1 Release 及其安装包继续作为回退入口。

初步对比发现，0.3.2 将入口由点击/长按手势识别器改为 UIControl 的 begin/continue/end tracking，并改动了入口动画、触摸区、取消时序、面板复用和日志 flush。根窗口 hitTest 适配、浮动 scene 启动和 binder 销毁没有修改。

继续调查确认了直接接口错误：0.3.2 的 `beginTracking:withEvent:`、`continueTracking:withEvent:`、`endTracking:withEvent:` 缺少 `WithTouch`，没有覆盖 SDK UIControl 的对应方法。Clang 将其接受为普通新增方法；旧版同时没有点击识别器，所以这条入口激活路径不可达。SDK 声明和实际源码 AST 是证据，不能由此推断所有 guest 内容或系统触摸也有同一原因。

0.3.2 的 C 手势测试直接调用判定模型，无法证明 UIKit 会实际进入这些 tracking 回调；静态分析、原生编译与签名结构检查也不覆盖这一路径。此次设备反馈表明，离线检查通过不足以支撑入口行为有效的结论。

0.3.3 修复候选版纠正回调名；检查器在实际 0.3.2 源码上解析成功后因 selector 不匹配失败，在修复源码上通过。新增根查询、窗口入口投递、跟踪和面板阶段日志，供真机确认。日志缺失本身不能证明根因。0.3.1 仍有此前报告的入口难唤出和流畅度问题，作为回退基线保留；候选版只有经过 [设备验收](../device-validation-0.3.3.md) 才能确认实际效果。
