# HaruGalaxy 0.3.2 / 初春星河 真机验收

用户最新反馈：整体可用，但收起后的悬浮入口经常无法唤出，交互仍需更流畅。已有测试设备为 iPhone 14 Pro Max / iOS 16.2（20C65）；本轮没有新的设备日志或自动化 UI 测试，以下项目均待真机确认。

安装 `HaruGalaxy-0.3.2.tipa`（build 7），从 0.3.1 覆盖升级，Bundle ID 仍为 `io.github.airskotex.harugalaxy`。默认保持自动收起；可在设置 → 浮动工作区开启“入口保持展开”。

| 项目 | 操作与通过条件 |
| --- | --- |
| 收起后点击 | 左右两侧分别收起后点击 20 次，包含略偏内侧/上下的落点；观察立即展开反馈及面板是否打开，记录未响应次数 |
| 收放动画期间 | 自动收起时立即按下，或快速开、关、再开面板；每次有效点击只切换一次，不出现动画期间无法点击 |
| 短拉唤出 | 从凸起或其内侧触摸区向屏幕内短拉约 20–30 点后松手；左右均能打开，往回收回原位后松手不打开 |
| 轻微偏移 | 轻点时手指略微移动；长按振动前有小偏移，随后停住并松手；均应打开，不能误判为移动入口 |
| 故意移动 | 长按约 0.35 秒振动后再拖动，松手吸附边缘；不会同时打开面板，跨边缘后凸起贴合新边缘 |
| 中途取消 | 按住或拖动期间锁屏、切换宿主或旋转；取消后不突然打开，移动取消恢复原位置，再次触摸可正常使用 |
| 保持展开 | 开启设置后持续展开，退出重开设置值保留；关闭后恢复收起，不改变已有窗口和入口边缘位置 |
| 内容触摸 | 入口之外的系统/App 控件可用；56×76 点入口区域内用于唤出，如与 App 按钮冲突可移动入口；检查系统边缘手势冲突 |
| 多窗口面板 | 保留最多四个窗口，重复开关、最小化、恢复、全屏和关闭；名称、状态、按钮行为与顺序及时刷新，最后一个关闭后显示空态 |
| 滚动与主题 | 四个窗口时滚动面板，关闭条目后不留下空白滚动区；切换深浅色，活动/非活动窗口边框正确 |
| 流畅度 | 与 0.3.1 对比反复开关面板、前后台切换和拖动；区分入口响应、面板出现、App 内容更新是否卡顿，记录操作和时间点 |
| 既有路径 | 后台浮窗、搜索键盘/主应用输入兼容、右上自由/右下原始比例缩放、上下半屏和全屏仍可用 |

遇到问题后进入设置 → 真机诊断 → 标记刚发生的问题 → 导出诊断包。保留详细日志开关，反馈当时在左/右侧、点击/短拉/长按中的哪一种、面板是否闪现、是否刚锁屏或旋转。

新增事件含义：

- `edge.touch_begin`：入口已收到按下事件。没有此事件时，应调查命中区域、系统手势或根窗口触摸路由；不能仅凭缺少日志判断原因。
- `edge.activate`：点击/原地长按、向内短拉或辅助功能触发了面板请求，`duration` 是本次触摸历时，不是输入延迟。
- `edge.touch_end` / `edge.touch_cancelled`：没有触发面板的结束/取消结果，便于辨别手势判定和外部取消。
- `edge.move_begin/end`：移动入口与取消结果；不采集连续手指轨迹。
- `panel.open` 的 `preparationMs`：同步创建/更新条目及布局耗时；不包含屏幕实际呈现、触摸送达或 GPU 帧时间。`rowsCreated` 为当前面板生命周期累计创建数；相同窗口反复开关时应不增加。

可使用 `python3 scripts/inspect_diagnostics.py <日志路径>` 查看事件。没有设备帧时间与对照记录，不标注具体 FPS 或百分比提速；主机测试验证判定模型，不覆盖 UIKit 的真实事件投递。
