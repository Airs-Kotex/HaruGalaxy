2026-11-08 开始实施，2026-11-09 整理交付。用户已确认源码路线和 `/root/UiharuXPro4MilkyWay` 工作副本。

## 交付范围

原生 Objective-C 工程、C 窗口状态模型、应用选择器、真实应用场景适配、窗口三键与几何操作、设置、实验性浮动根场景、构建签名脚本及源代码归档。应用内和浮动模式共用一个工作台，保持同 App 单一会话。

本次没有 iOS 真机，因此“真实小窗可操作”的验收仍待执行。功能代码和安装包已准备，不能将离线编译描述为真机功能通过。

## 代码复核中修正的问题

- 关闭场景使用其实际唯一 ID，清理不发送 SIGTERM/SIGKILL。
- 启动取消、重复 completion、迟到的浮窗连接有状态与身份检查。
- 浮动模式复用同一工作台，关闭或断开后恢复主窗口并清理 host 状态。
- 普通模式退后台、浮窗锁屏时同步 guest 可见性；恢复不激活最小化窗口。
- 激活 presenter 后再检查视图；失败/重试明确移除之前附加的 guest 视图。
- 恢复失败时保留实际错误信息。
- 缺少 Git 的源码副本仍能构建，来源读取归档元数据，后续本地编辑状态标为未知。
- 私有框架加载失败时尝试公共 Frameworks 目录，兼容 CoreServices 的实际位置。

## 与最初草案的明确差异

本次未移植 TrollSpeed 的独立 root HUD 或人工触摸分发，而采用 FrontBoardAppLauncher 的浮动根场景方式，减少同时引入多种输入机制。

没有移植上游 `FBSWorkspaceScenesClient` 对场景更新的拦截。浮窗是关闭默认状态的实验功能；binder 单独能否保持后台场景、空白穿透是否完整，须在真机确定。后续若引入拦截，必须限制到本项目拥有的根 scene，并验证系统回调的完整性。

当前启动成功表示取得并激活 native presenter，不是已观察到首帧。上游关于键盘、单场景 App 和重开的问题继续列入验收。

## 验证入口

- `make test`：状态机、非法/非有限几何、2,000 组边界、最大化/恢复、旋转。
- `make package`：完整 arm64/iOS 15 编译、链接、ldid 签名、打包并自动校验。
- `make verify`：包内容、plist、平台目标、签名结构和权限。
- `dist/build-report.json`：当前产物来源提交、工具版本、SHA-256，`device_tested` 固定记录为 false。
- `docs/device-validation.md`：必须由设备操作确认的项目。

源码包可通过 `python3 scripts/export_source.py` 重新生成。源码与应用产物分别导出；SDK 和下载缓存不进入源码归档。
