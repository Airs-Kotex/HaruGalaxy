# 0.3.15 / build21：托管方向选择与系统旋转通知

本版延续0.3.14的场景坐标和新会话启动流程，集中修正托管应用的横竖屏方向选择。
代码、离线验证和限定范围独立审查已完成；没有本版真机或模拟器验收结果。

## 方向来源

通过动态运行时检查接入`FBSOrientationObserver`，校验初始化、handler、invalidate及整数getter的可用性和类型。
系统回调切到主线程，并用弱引用和generation隔离停止/恢复期间的旧回调。观察器不可用时沿用UIDevice/CoreMotion。
没有扩大签名权限，也没有强行旋转系统自有的呈现视图。

UIDevice的前台缓存只作独立回退源，激活时先读取合格种子，再应用系统方向。
重复旧重力值不覆盖新系统方向；新测量的稳定重力仍可驱动普通和浮动工作区，保留旋转锁定下的跟随行为。
平放或无法分类时保留有效方向，隐藏/锁屏时停用观察。

## 托管应用约束

每个会话保存有效运行时支持掩码；读取为0或不可用不代表禁止旋转，也不会单独清掉旧掩码。
尚无有效运行时掩码时使用应用声明；iPad优先读取对应声明。多方向应用的客户端方向可能只是宿主请求的回声，
因此不会在未知掩码时无条件采用客户端回报。受约束的应用在支持范围内选择方向。

每次有效非零掩码重新建立确认周期，包括相同数值重申。当周期曾收到允许方向后，
未知掩码加有效冲突方向才可使缓存失效。客户端连接和设置变化都在回调入口捕获方向/掩码数值，
随后交主线程应用，避免本项目额外排队后重读最新设置、丢掉中间匹配状态。

画布轴向、等比比例、挂起内容尺寸及场景提交与选定托管方向一起更新。外框仍遵守用户的窗口布局选择；
仅竖屏的应用不会因为自由缩放成宽窗口就被强制横屏。

## 已知边界

- `24/3→24/1→0/1`可表示重申横屏后的旧方向，也可表示退出全屏时方向先变。仅凭这两个数值不能区分意图。
  本版优先保留新近有效的横屏掩码；明确的新竖屏掩码或新周期匹配后的冲突可解除约束，不保证所有退出序列。
- 回调入口捕获消除了本项目延迟重读造成的合并，但不能证明系统在回调前不合并、不并发、不乱序。
  私有getter的队列契约及数据与原事件的对应仍需设备确认。
- 观察器实际投递、横屏画面/边缘触摸、安全区、旋转锁定和恢复未做真机验证。方向日志与提交成功不是渲染成功的证明。
- 竖屏工作区最大化横屏内容可能出现较窄的等比内容区域。原始画布仍只是布局选项，不保证修复键盘或缺失图像。

## 验证

15组便携C/UBSan与19项Python测试通过；包含方向回声闭环、24/0交替、同值重申、
掩码失效、9216组重复快照检查、积压观察的有序消费、激活顺序及四方向几何。
相关7个生产单元静态分析无告警；原生arm64构建与包校验结果记录在发布附件中。

独立审查对最终修正及必要调用链给出限定范围通过，并独立执行方向检查和合成状态探针。
没有把合成测试、构建或审查结果写成设备验收。设备步骤见[本版验收表](device-validation-0.3.15.md)。
