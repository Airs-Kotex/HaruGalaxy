# 0.3.17 / build23：自由与等比缩放双向切换

本版修正0.3.16中连续“等比→自由→等比”或“自由→等比→自由”后，应用内容仍沿用旧画布比例的问题。原因为画布建立后只随方向换轴，缩放手势结束时没有采用新模式的画布。生产Core基线探针可复现这一机制；本版没有真机或模拟器验收结果。

## 行为

- 拖动中保留当前App画布，完整等比适配外框，必要时留边，不逐帧重排应用内容。
- 普通自由缩放成功松手后，按最终内容视口更新画布，并遵守App自身的方向约束。
- 普通等比缩放成功松手后，恢复当前方向的系统原始画布。
- 原始画布模式始终使用设备画布；取消、失败或不足14点的轻微拖动保留原状态。

成功松手时先完成外框与内容区域的最终布局，再选择画布并统一提交场景几何；停止待提交的预览更新，重复的尺寸、方向及安全区不重复提交。普通应用会在成功松手时按选定模式重排。这取代0.3.16“松手后继续保留旧画布”的行为，不保证所有应用都没有视觉跳变。

半屏、最大化与还原继续使用原有状态恢复路径；没有扩大进程重启、主题、方向来源或键盘逻辑的修改范围。

## 验证与限制

- 16组C/UBSan、19项Python测试通过，覆盖五轮双向切换、设备尺寸与方向约束、原始画布和恢复状态。
- 原生arm64构建与包校验通过；两个变化实现单元静态分析无告警。
- 限定范围独立审查通过，无新增发现。审查员独立运行冻结Core测试，并验证9216个四角阈值/终态组合及768组五轮双向切换。
- 上述探针使用生产Core和UI顺序等价模型，不是UIKit执行证据；实际手势、取消、渲染、触摸及FrontBoard投递仍需设备验收。
- 既有实时主题、手机方向、键盘及部分应用缺失图像问题不在本轮新增修复保证内。

验收步骤见[设备检查清单](resize-theme-validation.md)。历史0.3.16及更早发行保留，0.3.2与0.3.11维持撤回。
