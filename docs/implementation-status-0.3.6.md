# 0.3.6 自由拖动与 guest 键盘

用户确认 0.3.5 主应用键盘已可用，但 guest 键盘仍不可用；另反馈入口无法自由移动、右下角等比缩放难触发。本轮没有新的设备诊断包，不能将 guest 输入假设当成已复现的设备根因。

代码层面确认入口存在两项限制：移动必须先满足0.35秒长按，早期位移可被判为拒绝；位置只保存左右侧和垂直比例，释放后必定贴边。现在12pt位移直接转入拖动，之后回到起点也不激活面板；保存x/y归一化位置，仅在距离侧边18pt内释放才吸附。加载时兼容原有边缘位置，旋转按比例重新布局，取消则恢复起点。行为模型和边界测试覆盖直接拖动、误触容错、位置保存/恢复、小视口与旋转。

自由入口居中时面板优先向可容纳的侧边或上下展开；小屏横屏使用较窄侧边，小屏竖屏使用紧凑标题区，保持至少98pt窗口条目视口。独立复核发现的667×375、320×568案例分别先复现了列表过矮和入口遮挡，再以回归测试验证修正。

标题栏允许pan从按钮开始，移动由识别器取消button tap，普通点按仍执行原动作。两个缩放控件从28pt扩大到44pt四分之一圆命中区；弧线视觉大小保持原样，接触时加亮，右下拖动仍使用系统原始比例，不新增点按缩放。

guest键盘原来只有PID登记和焦点请求。根据固定MTACS `_UIKeyboardArbiterClient` 协议声明补充 `prepareForHostedWindowWithScene:` / `finishWithHostedWindow`，只使用成对可用且ABI匹配的方法。准备的窗口由UIKit管理，本项目不重设它的根控制器/层级。旧PID关系未清除时不释放显示上下文、不加新关系；finish失败时保留对象以重试。切回宿主搜索仍清理guest显示上下文。

另通过 `FBSceneObserver` 的 `scene:didUpdateClientSettingsWithDiff:oldClientSettings:transitionContext:` 读取guest的 `systemInputActive`；已有进程监测也按两秒间隔补查。只记录变化，不写入输入内容；只允许同一宿主窗口且仲裁owner仍匹配的guest刷新焦点，延迟通知不能替换已选择的面板/宿主输入。焦点请求后0.35/1秒记录实际状态，completion仍不视为grant。

新版诊断用于区分guest未请求输入、托管显示未准备、焦点源不匹配与键盘未显示。宿主输入的用户成功反馈不延伸为guest成功。0.3.6 / build11沿用原Bundle ID，设备行为仍需日志确认。
