# 0.3.9 设备反馈

版本0.3.9/build14。底部8pt，标题28pt；移除复制输入板。直接guest键盘仍未宣称可用。

1. 在已打开的小窗中选择需要输入的App。
2. 面板 → 设置 → 真机诊断 → **采集键盘诊断（20秒）**。设置会关闭，采集随即开始。
3. 20秒内先点目标小窗标题，再点文本框；若方便，再切换到另一App文本框。记录光标、键盘画面和实际输入各自是否出现。
4. 在设置标记问题并导出诊断包。要比较主工作台与桌面浮窗，可分两次采集；不要仅提交旧0.2.x日志。

| 其他检查 | 预期 |
| --- | --- |
| 底部触达 | 从8pt细边左/中/右按住拖动，等比缩放；细边外的App操作不被拦截 |
| 比例/全屏 | 自由拉伸后从底部进入系统原始比例；全屏没有底边 |
| 原应用交接 | iOS16.2缺少deactivate:时选择settings update路径，而不是直接关闭并提示不支持 |
| 预检不支持 | 两条路径都不可用时显示提示，原小窗仍可操作 |
| 超时/取消 | 交接期间锁屏/切后台不会稍后突然打开原应用；面板遮罩不留在原应用上方 |
| 输入板移除 | 面板没有复制输入板，“打开应用”恢复整行；主应用搜索仍可输入 |
| 采集结束 | 最多21次定时样本，20秒后停止；主线程暂停后不会补发一串旧样本 |

采集字段包含：运行时类/selector与编码，guest输入活动、可见/托管状态、焦点归属、键盘窗口hidden/alpha/level、可见性环境桥是否应用，以及宿主实际收到的guest触摸起始次数。WindowServer可能直接转发guest触摸，计数为0不证明未触摸。采集不读取文字、按键、剪贴板或画面，也不调用新的焦点选择接口。

`keyboard.diagnostic_sample`的reason为capture/problem_marker/export；后两种快照不属于定时次数。`native_handoff.capabilities.route`为1代表deactivate，2代表settings update，0代表无可用路径。`background_acknowledged`需要配合foreground与accepted观察；这些都不等于原应用已经绘制或键盘可用。
