# 0.3.7 设备检查

版本0.3.7 / build12。用户反馈0.3.6之后右下缩放仍难触发、guest键盘不可用。此版本将右下角与guest内容物理隔开，输入板复用普通场景系统键盘；不宣称直接guest输入已经恢复。

| 项目 | 操作与观察 |
| --- | --- |
| 右下等比 | 在底栏右下淡色方块的中心、左上边缘及弧线分别按下拖动；应加亮并开始缩放，不触发App底部按钮 |
| 原始比例 | 右上自由拉成宽窗，再从右下等比区拖动；内容应回到当前方向的系统原始比例 |
| 半屏/全屏 | 上下半屏均有独立底栏；全屏隐藏底栏并保持完整内容，通过面板还原 |
| 定向输入板 | 小窗底栏键盘图标 → 输入中英文、换行、emoji → 复制并返回 → 在原文本框长按粘贴 |
| 通用输入板 | 边缘面板顶部“输入板”，没有guest窗口时也可进入；取消不改写剪贴板 |
| 全屏输入 | 全屏窗口通过面板该App条目的键盘图标进入输入板，再返回全屏 |
| 横屏 | 输入板旋转为横屏，编辑区保持在键盘上方；空间不足时原应用动作移到导航栏 |
| 原应用 | 底栏打开原应用图标或输入板“在原应用中输入”；所有托管画面收纳，普通App文本框可使用系统键盘；面板可恢复原窗口 |
| 启动中窗口 | A仍在加载时选择B的原应用输入，A晚到的加载/失败回调不能重新覆盖原应用 |
| 取消与恢复 | 输入板取消、返回、锁屏、切后台或关闭浮动模式后不残留键盘、不重新抢焦点、不出现旧草稿 |
| 原有功能 | 主应用搜索、入口自由拖动/贴边召回、最小化和关闭保持可用 |

`input_board.focus.accepted`只表示UITextView接受第一响应者；`input_board.keyboard.overlap`记录键盘与输入板的交集高度。`input_board.finished.copied`只表示用户明确复制，不等于guest插入成功；`input_board.original_open.accepted`也不等于普通App已经显示。结合`search.*`和`overlay.search_input`可还原切换过程。

右下触摸关注`window.resize_contact`、`window.resize_begin`和`window.resize_finished`；配合`window.content_geometry`检查内容区是否与底栏分离。诊断不记录输入文字。出现问题后标记并导出本版本日志；旧版本日志不能验证本版路径。
