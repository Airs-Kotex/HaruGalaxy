# 0.3.7 独立缩放区与输入板

用户继续反馈右下角可能命中guest操作，且guest键盘依旧不可用。本轮没有新的设备日志；先前已确认主应用搜索键盘可用，因此沿用该普通场景输入路径，而非把新的私有焦点调用视为成功。

代码可确认0.3.6的右下角覆盖guest呈现区域，44pt四分之一圆命中并未提供独立空间。0.3.7保留44pt底栏，guest高度由共同的纯C几何函数扣除48pt标题与44pt底栏。右下角使用完整方形命中、接触加亮，并在本窗口局部hitTest中优先判定。全屏没有底栏，仍铺满显示边界。纯几何测试覆盖不相交、原始比例、顶部额外安全区、极小边界和全屏；本机检查不能证明远程WindowServer实际触摸路由。

新增MWInputBoardController，使用普通应用场景中的UITextView。窗口底栏、面板通用按钮与每行键盘按钮均可进入。复用MWSearchHandoff的代际、前台激活和超时机制，使用具体导航控制器身份确认回调归属。等待输入期间暂停guest可见性和输入登记；复制、取消、后台、锁屏和超时均清除草稿/延迟焦点并恢复适当工作台。短横屏隐藏说明和底部动作，将原应用入口移到导航栏，避免编辑区延伸到键盘下方。

输入文本只在用户点击“复制并返回”时写入本机剪贴板，设置10分钟过期；不读取其他App剪贴板、不保存草稿、不注入guest、不记录字符。返回后由用户在目标文本框长按粘贴。原应用入口从现有窗口注册表取目标标识，收纳所有托管画面，再调用已检查ABI的LaunchServices打开接口；启动中和失败的画面也移出视图层级，防止晚到回调覆盖普通App。拒绝请求时按原层级和状态还原；接受后只通过面板显式恢复窗口。普通App的场景不保证保留guest表单或光标。

诊断阅读器新增独立的input_board_pipeline，区分第一响应者接受、键盘交集、明确复制和原应用打开请求；这些阶段不推断粘贴成功或前台状态。开发构建、纯C测试、Python回归、静态分析和归档重建的结果随发布验证报告记录；0.3.7没有真机验证结果。
