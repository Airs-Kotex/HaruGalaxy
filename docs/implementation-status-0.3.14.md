# 0.3.14 / build20：iPad 横屏坐标与进入小窗前重置

最新反馈是iPad7,5/iPadOS16.3(20D47)、0.3.13/build19的3BEF诊断。文件包含7385事件、4次启动，仅最后475事件归属本版。旧0.3.10记录不参与当前归因，原始日志保留本地。

## 横屏证据

设备/宿主已经报告方向3、1024×768，不能把故障简单归因为没有横屏通知。presenter.transform为[0,1,-1,0,0,0]；wrapper初始又设置bounds1024×768，后续UIKit将其改为547.19×850.92，而请求内容是850.92×547.19。原实现混用了native scene与内容坐标，且反复覆盖UIKit自有几何。

创建和resize统一使用横屏宽高交换后的native scene frame。UI wrapper不再写presenter的bounds/center/transform，用自有容器对其实际局部映射求逆，再等比适配内容范围。原生容器的bounds覆盖旋转后的完整子视图，不会仅显示正确却在右侧提前拒绝touch；坐标采样包含bounds origin/平移。场景更新完成及client变化后刷新。日志记录请求/报告frame、client方向及normalization矩阵。

在当前trace里UIDevice更新只发生于启动。新增5Hz CoreMotion重力方向，两个稳定样本后改变方向，平放/斜角保持旧方向；只在可见工作区有窗口时启用，隐藏/锁屏停止并废弃排队回调。没有记录原始传感器样本。系统仍可能不投递，此时日志报告来源状态和最近样本年龄。

## 双重声音处理

日志只有一个hosted scene/PID，不能用两个图层断定两个播放器。用户听到两路声音且代码无进入时清理旧运行路径：`identityForEmbeddedApplicationIdentifier`会解析应用进程，新scene可以与原应用页面同时存在。

新会话先解析精确process handle，通过现有结束请求等待该实例退出，再启动新进程并建scene；未确认退出、拒绝、返回同一PID都不会建立新小窗。既有最小化/挂起恢复不重新启动；显示模式重开属于新会话，也会重置进程。用户选择列表和README说明可能丢失未保存内容、当前页面与播放位置。不同App各自播放不受影响，不发送全局暂停命令。

reset登记在主线程集合，取消原会话仍保留未完成标记，避免迟到结束请求打中替代小窗；Close期间等待同一次结束结果而不发重复请求。原应用切换及画布重开在reset/launch未完成时拒绝，防止提前foreground后被迟到结束。完成只根据进程消失观察；没有将request acceptance当退出。

## 离线验证和限制

14个便携C套件（UBSan）覆盖scene-frame转换、四方向/负平移的归一化及ancestor命中范围、重力方向过滤、重置/重启/取消/交接状态；Python日志工具19项测试。原生arm64编译启用warnings-as-errors；发布报告保存最终静态分析及CI结果。独立复核的横屏容器命中范围与reset期间原生跳转缺陷已修正。

没有iPad/iPhone设备或模拟器可实际播放。尚须真机确认横屏画面/触摸、传感器投递、终止权限和单路音频；目标App也可能自己恢复多个播放器。键盘和其他应用图像问题本版未宣称修复。发布为独立0.3.14，保留旧发布；0.3.2、0.3.11继续撤回。
