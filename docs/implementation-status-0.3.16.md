# 0.3.16 / build22：稳定缩放画布与浮窗主题同步

本版基于0.3.15的iPad设备反馈修正普通窗口缩放布局、浮窗主题同步，并补齐可见工作台后台方向通知的回退路径。代码、离线验证与限定范围独立审查已完成；没有本版真机或模拟器验收结果。

## 缩放与初始方向

普通窗口的四个缩放入口保留正在运行的应用逻辑画布，内容完整等比适配外窗。右上/左下独立调整外框宽高；左上/右下以系统原始比例调整外框内容区域。比例不同会留边，不再在切换缩放入口时突然把应用内部尺寸改为完整设备画布，也不在自由拖动中持续改变应用内部宽高。

首次布局在托管会话建立前只作为预览。解析应用方向后才初始化保存画布，尺寸与对应方向一起记录；后续真实切轴交换一次。取消手势、失败重试和初始最大化后还原都沿用这一状态，避免方向与尺寸分离。

普通模式的半屏与最大化仍是明确的布局操作，允许应用按目标视口重排；最大化还原恢复窗口画布。原始画布模式始终使用设备画布。上述变化不重启正在缩放的应用，也未更改键盘托管和进程退出权限。

## 浮窗主题

同一协调器将主题偏好应用于应用窗口与浮窗，工作台控制器随所属窗口继承样式。通过可用的UIKit系统样式通知及受保护的系统样式读取更新自动主题；读取不可用时，新连接、进入前台或样式确实变化的普通场景可提供降级快照。旧后台场景和已被手动设置样式的浮窗不作为新的系统样式来源。

系统状态与手动偏好分开，切回“跟随系统”使用最近有效系统值。通知入口和快照读取时记录观察序号，较早排队的通知不能覆盖更新的观察；同值的新快照也推进顺序。此保护处理本程序内的排队交错，不证明系统在通知入口前没有合并或乱序。

## 方向回退

可见浮窗可能保持活动而普通应用已处于后台，此时接受新的UIDevice方向通知作为回退。后台启动缓存仍被拒绝，近期CoreMotion输入优先，隐藏、停止和旧代次回调保护保持。此前收到的诊断仅来自iPad，不能据此证明手机横屏故障的实际原因或修复效果。

## 验证与未验证项

- 16组C/UBSan与19项Python测试通过，包括64组启动方向/形状组合，以及生产主题状态的降级、手动切回自动和消费顺序回归。
- 原生arm64构建、安装包校验通过；9个相关实现单元静态分析无告警，未变化单元复用已核验结果。
- 独立审查先发现并复核修正了初始画布换轴、主题旧缓存阻断降级两项问题；最终限定范围通过，无新增发现。另独立运行冻结Core测试与256个生命周期、31104个主题来源/消费顺序组合，均为离线模型。
- UIKit私有通知/读取接口的实际可用性、后台事件投递、真实手势、显示和触摸、iPhone旋转仍待设备验收。原始画布只决定布局，既有键盘和部分应用缺失图像问题没有宣称修复。
