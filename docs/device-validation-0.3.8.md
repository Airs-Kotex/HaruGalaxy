# 0.3.8 设备检查

版本0.3.8/build13。0.3.7用户确认独立底栏可触发等比缩放，但占用太大；复制输入板不足以解决键盘，原应用切换呈白屏。本版没有新的设备日志。

| 检查 | 操作与观察 |
| --- | --- |
| 画面占用 | 标题28pt、底条18pt，总计46pt；底部没有键盘、原应用按钮或提示文字 |
| 等比触达 | 从底条左、中、右三个位置分别拖动；均触发原始比例缩放，不操作App内容 |
| 自由与半屏 | 右上自由调整后拖上/下半屏，再底条等比；内容不与控件重叠 |
| 紧凑标题 | 关闭/收纳/最大化普通点击有效，从按钮拖动不执行点击；面板保留较大操作按钮 |
| 原应用切换 | 面板对应App的↗结束目标小窗后打开原应用；原窗口条目消失，其他窗口仍能从面板恢复 |
| 白屏复查 | 对原来白屏的同一App切换，记录是否仍白屏；不要将请求被接受当作显示成功 |
| 竞态 | 等待交接时锁屏、切后台或停用浮动模式；解锁后不突然打开原应用 |
| 面板遮罩 | 交接等待时连续轻点边缘入口；原应用打开后不遗留面板或全屏点击遮罩 |
| 失败窗口 | 小窗启动失败时从面板切原应用；原小窗已清理的情况下仍可发起启动 |
| 启动中切换 | guest仍加载时切原应用；旧launch callback不能重新附着窗口 |
| 键盘定位 | 小窗点击文本框、全屏点击文本框、原应用点击文本框分别尝试；记录光标/键盘/实际输入三项 |

反馈前在设置“标记刚发生的问题”，导出0.3.8诊断包。直接guest输入仍未解决，需要当前日志区分未请求输入、焦点拒绝、键盘未显示及场景冲突。日志不记录输入文字。

`native_handoff.deactivating/deactivated/released/open_requested/finished/cancelled`记录交接各阶段。`localReleaseConfirmed`只确认本地场景管理器已移除及调用清理没有异常，不证明远端进程已经绘制普通场景。结合`guest.*`、`keyboard.*`、`window.content_geometry`和问题标记判断。
