# 0.2.0 真机反馈迭代

用户反馈基线：iPhone 14 Pro Max / iOS 16.2；0.1.0 已运行并呈现预期界面，但开启浮窗后不能继续后台运行。用户要求兼顾所有 TrollStore 用户、边缘小凸起入口、详细可导出日志，并追加等比缩放。沿用已批准的源码路线和工作目录，继续执行这些明确要求。

## 后台

代码证据：0.1.0 仅创建本地根 scene/binder，无持续执行 assertion，无场景降为后台的保护。使用当前进程的 BKSProcessAssertion（PreventSuspend + PreventThrottleDownCPU + AllowIdleSleep，Continuous reason），明确记录 valid/失效，退出浮窗时释放。不采用有限时长的 UIKit background task 充当持续后台能力。

对本进程 FBSWorkspaceScenesClient 的 scene 更新增加检查过签名的适配。仅对本项目当前拥有且未锁屏的 overlay scene 生效；使用语义 settings/diff API 重建 foreground/deactivation 更新，并且原始方法和 completion 始终执行一次。不会操作其他 App 或系统进程的实现。运行时接口缺失时保留原路径并记录诊断。

替代方案为独立 root HUD 进程，但这会新增跨进程窗口转移、输入分发及偏好同步。先完成现有 FrontBoard 路径和日志以定位 iOS 16.2；若设备证据显示进程级托管仍不成立，再决定是否引入该后端。

## 边缘入口

默认吸附屏幕右边，可沿边拖动并切换左右；闲置收为 8×48pt 凸起。命中区域保持 44pt，点按展开，再点打开应用；向内拖动也展开。展开后 3 秒无操作收回；长按进入设置。位置保存为边与归一化纵坐标，横竖屏变化保持可触达。

## 等比缩放

内容区比例与场景逻辑尺寸一致，标题栏固定 48pt，按钮触达至少 44pt。使用统一 scale 对真实 presenter 的视图变换，场景逻辑尺寸不随每个拖动采样变化。缩放、最大化和横竖屏重排都保持内容比例；不足最小尺寸时以视口容纳为先。纯 C 几何模型覆盖比例、边界和旋转测试。

## 日志

默认详细日志，JSON Lines，串行写入，4×2MiB 滚动。记录 App/scene 生命周期、进程与 scene ID、启动阶段、异常、assertion 申请/失效、guard 修改与透传、前后台/锁屏、旋转和手势起止。5 秒运行采样记录 uptime、内存及间隔，帮助识别暂停/恢复；没有日志间隔只能作为线索，不能据此断言崩溃。

启动与导出记录型号、系统 build、应用版本、平台能力检测、签名权限观察和本次会话标识。记录未捕获的 Objective-C 异常，保留上一会话结束标记；不拦截 fatal signal，避免破坏 iOS 自身 crash reporter。

设置中提供详细记录开关、标记刚发生的问题、导出诊断包、清空日志。导出为单个 JSON 文件，包含元数据、能力、事件日志和回收统计；使用系统分享面板交给用户保存/发送。不自动上传、不采集屏幕、输入文本、账号或完整已安装应用列表。

## 兼容范围

将宿主最低部署目标降至 iOS 14.0，以覆盖 TrollStore 可安装版本；对 iOS 15 新 UIKit 样式做可用性回退，对私有 scene/assertion API 逐项检测。iOS 14 的外部 scene 能力仍受上游已知限制，需要单独测试，不将安装可用等同于全部窗口功能已验证。记录矩阵：14.x、15.x、16.0–16.6.1、16.7 RC、17.0；不宣称整个 14–17 范围都可安装 TrollStore。

## 验收

主机：Core 比例/边缘/状态测试，日志滚动与导出结构、版本元数据、完整编译和签名；代码复核关注 hooks 透传、锁屏、assertion 生命周期、日志并发和分享文件生命周期。

真机：iPhone 14 Pro Max / iOS 16.2，开启浮窗后回桌面 30 秒和 3 分钟，操作小窗后导出；再验证锁屏/解锁、缩放和重开。后台修复只有通过这项设备反馈才能标记已验证。
