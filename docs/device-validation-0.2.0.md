## 建议反馈流程

1. 保持设置中的“详细诊断记录”开启。
2. 执行一次后台测试和一次锁屏恢复测试，记下大概发生时间。
3. 回到本应用，设置 → 真机诊断 → 标记刚发生的问题。
4. 选择“导出诊断包”，将 `UiharuX-Diagnostics-….json` 保存后提供给开发者。
5. 同时描述：测试的 App、等待多久、画面消失/冻结/无法触摸中的具体一种现象。

如果本应用被系统结束，重新打开后再导出，日志轮转会保留前次事件；末尾中断记录会修复。`session.previous` 中缺少正常结束标记不等于崩溃证明，iOS 也可能暂停或结束后台进程。

## 诊断事件

- `background.requested` / `background.status`：请求是否真正 valid。
- `guard.installed` / `guard.normalized` / `guard.passthrough`：适配是否安装、是否接收并处理自身浮窗更新。
- `host_scene.*` / `overlay.*` / `workspace.visibility`：哪一个场景进入后台、断开、隐藏或恢复。
- `guest.*`：目标进程、场景、presenter 与异常。
- `window.geometry_committed` / `edge.*`：等比窗口和边缘入口操作。
- `heartbeat.gap`：运行采样间隔；结合前后台和锁屏事件分析，不能独立判定原因。
- `exception.uncaught`：未捕获的 Objective-C 异常。fatal signal / jetsam 仍需系统原始 crash log。

导出含原始日志文本，遇到异常 UTF-8 会以 base64 保留并在 `exportErrors` 标出。`recoveredTailBytes`、`dropped` 与 `storage` 字段用于检查日志是否发生丢弃或存储故障。
